# 规则 11 —— 禁止非必须路径依赖

**强制执行：** `PreToolUse(Edit|Write)` —— 新写的代码里出现 user-home 绝对路径（`C:\Users\<name>\…`、`/home/<name>/…`、`/Users/<name>/…`，裸分隔符或转义分隔符均算）、字面量 `$HOME` / `%USERPROFILE%`、或带引号的 `~/…`，且相邻注释没有理由 token，即 DENY。系统根、裸盘符与相对路径不标记；散文文档与锁文件不扫描。

## 原则

> **一个只对某台机器、某个用户、某次 checkout 有效的文件系统路径，
> 不得作为绝对字面量写死进代码。** 从运行时已知的基准派生路径 ——
> 插件根目录、当前工作目录、一个环境变量，或一个传入参数。

机器特定的绝对路径是一颗可移植性地雷：它在作者机器上能跑，在其它每台
机器、CI runner 和容器上都会崩。本仓库亲历过这个失败 —— 曾有一次热修
就是给它*自己*钩子里一个 Windows 路径可移植性 bug 打的（一个含 `~` 的
runner `$TEMP` 让路径正则无法解析）。规则 11 把"别硬编码 user-home 路径"
变成一条写入时、根因层面的纪律（规则 03）。

## 范围 —— user-home 根是硬强制的那一类

忠于保守探测器哲学（"宁可漏报不误报"），只有锚定在**用户特定根**的
路径在写入时被拒 —— 这一类几乎从不合法可移植：

| 类别 | 硬强制？ |
|---|---|
| Windows user-home 绝对路径（`C:\Users\<name>\…`，裸或转义分隔符） | ✅ 是 |
| POSIX user-home 绝对路径（`/home/<name>/…`、`/Users/<name>/…`） | ✅ 是 |
| 字面量里的 shell home 变量（`$HOME`、`%USERPROFILE%`） | ✅ 是 |
| 字符串字面量里的 user-home 波浪号路径（`"~/…"`） | ✅ 是 |
| 系统路径（`/etc/…`、`/usr/…`、裸 `C:\`） | ❌ 仅软提示 |
| 相对路径（`./data`、`../lib`） | ❌ 放行（本就可移植） |

系统根与裸盘符**故意不**标记：它们常常合法固定，为它们做硬探测会在
正确代码上误触发。相对路径是我们想要的结果，不是违规。紧贴主机名的
`/home/<x>/` 段也不标记 —— 在 `https://host.test/home/alice/dashboard`
里它是 URL 路由而非文件系统路径 —— 而 `file:///home/…` URI 仍然命中，
因为那确实是机器路径。散文文档与锁文件豁免：文档里满是示意性路径，
锁文件也合法地记录解析出的绝对路径（规则 10 的 `requirements*.txt` /
`constraints*.txt` 例外同样适用于本规则）。

探测器想让你转而使用的可移植替代：
`Path(__file__).resolve().parent…`、`os.environ["CLAUDE_PLUGIN_DATA"]`、
运行时计算的 `Path.home()`（而非字面量）、一个 CLI 参数，或一条相对
仓库根的路径。

## 标注必须保留的路径

用户的范围是*非必须*路径依赖。一条必须的、真正固定的路径（一个有据的
示例、一个钉在已知布局上的测试 fixture、一个真的挪不动的平台路径）在
其所在行、或紧邻行（±1）的**注释里**携带理由 token 时被放行 —— 与规则 10
同一条逃生口、同一份 token 表（`because` / `因为` / `essential` /
`example` / `fixture` / `placeholder` / `sample` / `test data` …）。一条
没有任何理由的裸 user-home 路径 = 非必须情形 = **DENY**。

## 必须做（MUST）

1. **派生，别硬编码** —— 从插件根、cwd、环境变量或参数计算路径，
   让同一份代码能在任意机器上跑。
2. **优先相对路径** —— 把数据 / 配置锚在仓库或模块上，而非
   `/home/<你>` 或 `C:\Users\<你>`。
3. **标注真正的 fixture** —— 若某路径确实必须是固定字面量，加一条相邻
   理由，让检查能区分意图与偷懒。

## 禁止做（MUST NOT）

- ❌ 把 `C:\Users\<name>\…` 或 `/home/<name>/…` 烤进发布的代码。
- ❌ 把 `$HOME` / `%USERPROFILE%` / `~/…` 硬编码成字符串字面量。
- ❌ 假定作者的目录布局在其它每台机器上都成立。
- ❌ 在一条真实依赖上用假理由压制探测器。

## 关系

| 关系 | 说明 |
|---|---|
| 11 vs 03 | 03 说修根因；11 把"派生路径、别把机器写死"变成一条硬性、写入时的可移植性修复。 |
| 11 vs 09 | 同一机制（带 why 注释逃生口的写入时内容探测器）；09 针对屏蔽标记，11 针对机器特定路径。 |
| 11 vs 10 | 姊妹探测器；10 管*内联的是什么*（密钥），11 管*它指向哪里*（机器特定路径）。 |

## 自检触发

- 正要粘贴一个以 `C:\Users\` 或 `/home/` 或 `/Users/` 开头的绝对路径。
- 在代码里把 `$HOME` / `%USERPROFILE%` / `"~/…"` 写成字面量。
- 这条路径正确的唯一理由是"它在我机器上能跑"。
- 把你自己 shell 里的路径直接抄进要发布的源码。

## 终止条件

写一个绝对文件系统路径，只有满足**其一**才被允许：

1. 它在运行时从已知基准（插件根 / cwd / 环境 / 参数）派生，
   而非机器特定字面量；或
2. 它是明显的示例 / fixture（并如此标注）；或
3. 有一条相邻理由明确说明它是必须的。

否则 → **非必须路径依赖**，回到规则 03 把它派生出来。
