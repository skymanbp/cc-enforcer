# 规则 10 —— 禁止非必须硬编码

**强制执行：** `PreToolUse(Edit|Write)` —— 新写的代码里出现密钥命名的标识符或带引号键赋 8 字符以上的字面量、私钥 PEM 头、AWS access-key 或服务商签发的 token 字面量（`ghp_…` / `xox…` / `AIza…`）、URL 内嵌凭证，且该值不是明显占位、相邻注释也没有理由 token，即 DENY。散文文档与锁文件不扫描（`requirements*.txt` / `constraints*.txt` 例外，仍扫）；魔法数字与裸端点只是提示。

## 原则

> **一个在设计上本应是变量的值 —— 应从配置、环境变量、密钥管理器或
> 传入参数读取 —— 不得被偷懒地内联成源码字面量。**

本规则拦截的典型偷懒就是"设计上应该是变量却被偷懒塞成硬编码内容"——
那些**毫无疑问本应活在代码之外**的字面量：

- 凭证：口令、API key、access key、auth token、client secret、bearer token；
- 私钥材料（PEM `BEGIN ... PRIVATE KEY` 块）；
- 嵌在连接串 / URL 里的凭证
  （`scheme://user:password@host`）。

硬编码密钥不只是脏，它把密钥泄进版本控制、CI 日志和仓库的每一份克隆，
还让轮换变成一次代码改动。把它外部化才是根因修复（规则 03）。

## 范围 —— 密钥是硬强制的那一类

忠于保守探测器哲学（"宁可漏报不误报"），只有**毫无歧义、本应是配置**
的类别在写入时被拒：

| 类别 | 硬强制？ |
|---|---|
| 密钥命名的变量或带引号键赋一个引号字面量（≥ 8 字符） | ✅ 是 |
| 私钥 PEM 头 | ✅ 是 |
| AWS access-key 字面量（`AKIA…`）或服务商签发的 token（`ghp_…` / `xox…` / `AIza…`） | ✅ 是 |
| 连接 URL 内的凭证 | ✅ 是 |
| 魔法数字 | ❌ 仅软提示（易误报） |
| 裸网络端点 / 端口 | ❌ 仅软提示 |

魔法数字与裸端点是*软*提示 —— 评审时提出即可，但**不**由钩子拦截，
因为为它们做硬探测会在合法代码上不停误触发。服务商 token 那一行也是
出于同一理由才取代"把裸 `token` 加进关键字表"：`token = "NUMBER_LITERAL"`
是普通的词法分析代码。

一个值被当作无害占位的条件是：它含有 `example` / `changeme` / `your-` /
`<…>` / `${…}` / `dummy` / `redacted`，或是一次环境读取（`os.environ[…]`、
`getenv`、`process.env`）；`:` 之后的纯字母 CamelCase 值（`password: "SecretStr"`，
一个类型注解）同样跳过。散文文档（`.md` / `.rst` / `.txt` / `.adoc`）与锁文件
豁免，因为它们合法地携带示例值、且是机器生成的；`requirements*.txt` /
`constraints*.txt` 仍被扫描，因为其中内嵌凭证的 index URL 是真实的泄漏向量。

## 标注必须保留的字面量

用户的范围是*非必须*硬编码。"必须 / 示例 / fixture"字面量在其所在行、
或紧邻行（±1）的**注释里**携带理由 token 时被放行：规则 09 逃生口的那些
token（`because` / `why` / `因为` / `原因` …）加上 `essential` / `必须` /
`必需` / `example` / `fixture` / `placeholder` / `占位` / `sample` /
`test data`。只认注释文本，而"注释"由词法判定 —— URL 里的 `#` 不算；
`/* … */` 块注释或独立成行的 docstring 算。一个没有任何理由的裸密钥 =
非必须情形 = **DENY**。

## 必须做（MUST）

1. **外部化密钥** —— 从环境或密钥库读取；真实值只留在未被追踪的
   `.env` / 密钥库里。
2. **标注真正的占位** —— 用明显的占位值，或加一条相邻理由注释，
   让检查能区分示例与泄漏。
3. **暴露即轮换** —— 若真实密钥曾被提交，视其为已泄露并轮换，
   不要只删掉那一行。

## 禁止做（MUST NOT）

- ❌ 把真实凭证 / token / 私钥作为源码字面量提交。
- ❌ 把口令埋进连接串。
- ❌ "临时"硬编码一个密钥，打算以后再外部化。
- ❌ 在真实密钥上用一条假理由注释来压制探测器。

## 关系

| 关系 | 说明 |
|---|---|
| 10 vs 03 | 03 说修根因；10 把"这个值属于配置而非代码"变成密钥类别的一条硬性、写入时的根因修复。 |
| 10 vs 09 | 同一机制（带 why 注释逃生口的写入时内容探测器）；09 针对屏蔽标记，10 针对硬编码密钥。 |
| 10 vs 11 | 姊妹探测器；10 管*内联的是什么*（密钥），11 管*它指向哪里*（机器特定路径）。 |

## 自检触发

- 正要在 `password` / `api_key` / `token` / `secret` / `bearer` 之后
  敲一个引号字面量。
- "只是为了先跑起来"而粘贴一个 key、token 或连接串。
- 把一个 `-----BEGIN … PRIVATE KEY-----` 块写进源文件。
- 对自己说"这个我以后再挪到环境变量里"。

## 终止条件

写一个含凭证的值，只有满足**其一**才被允许：

1. 它从环境 / 密钥库读取（非字面量）；或
2. 它是明显的占位 / 示例 / fixture（并如此标注）；或
3. 有一条相邻理由明确说明它是必须的。

否则 → **非必须硬编码**，回到规则 03 把它外部化。
