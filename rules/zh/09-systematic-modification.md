# 规则 09 — 系统式修改，禁止打补丁（systematic-modification · no-patch-style）

**强制执行：** `PreToolUse(Edit|Write)` —— 无理由的补丁标记（`try/except: pass`、`# noqa`、`# type: ignore`、`// @ts-ignore`、`// @ts-expect-error`、`// eslint-disable`、带 race / wait / workaround 注释的 `time.sleep`）即 DENY；同一文件本会话第 4 次小改（≤ 10 行且 < 200 字符）而中间没有一次系统式重写（≥ 50 行、≥ 1500 字符或 ≥ 文件的 30 %）即 DENY——净减少与记账类改动（升版本号 / 改日期）永不计数；`PreToolUse(Bash)` —— `--no-verify`、`--no-gpg-sign`、`chmod 777`、`git rebase --skip`、`--break-system-packages`、打到根路径 / `$HOME` / `~` 的 `rm -rf`、`git push --force`（`--force-with-lease` 除外）即 DENY；`Stop` layer (f) —— edit 轮的最终回复缺"根因 + 影响 + 方案"三件套且无 `rule 09` 标记即 BLOCK。

## 原则

> **修改必须是系统性的、完整性的更新，不是局部打补丁。**

打补丁式修改的典型特征：

- 看到症状改症状（"加一行 if 把异常吞掉"），不改根因；
- 局部塞 `try / except: pass` / `# noqa` / `@ts-ignore` / `// eslint-disable` 静音报错；
- 同一文件同一会话里反复小幅 `Edit`（rolling patches），每次只动几行——钩子对"小改"的界定是 ≤ 10 行且 < 200 字符；
- 在调用点局部包一层 wrapper / try 来"修好"，而真正的 bug 在被调函数；
- 把超时拉长 / 把断言放宽 / 把测试改宽容；
- 注释掉失败的测试而不是修代码；
- 在新代码里塞 TODO / "暂时这样" / "之后再做"；
- 对同一根因的 N 处症状逐个点对点修补，而不是在确诊的起源处做一次统一修复。

这些都不是"修复"，是**延后**问题。rule 09 把它们提到一类硬性禁令；标题下那一行说明其中哪些由钩子物理拦截。

## 必须做（MUST）

### 修改之前

1. **找到真正的根因**（rule 03）—— 不是"在哪里报错"，而是"为什么会这样"。
2. **确认根因证据**（rule 01 验证）—— 通过 Read / Grep / 命令输出**当场验证**根因假设。
3. **梳理影响范围**（rule 02 七问的"连带影响"）—— 列出根因牵涉的所有上下游。
4. **比较至少 2 个修复方案**（rule 08 第 6 项）—— 在简洁性 / 性能 / 与现有架构契合度 / 后续维护 4 个维度对比。

### 一个根因，一次统一修复

点对点打补丁——把每个观察到的失败当成一次独立的小修——被禁止。
问题出现时，唯一被接受的形态是**溯源 → 确诊 → 统一修复**：

5. **溯源到最上游根因**（rule 03 上游阶梯）：沿因果链上爬，直到答案
   是机制 / 设计决策 / 缺失不变量为止，并显式说明为什么停在你停下
   的地方。
6. **确诊先于动手**：根因假设必须在写下修复的第一行代码*之前*，被
   第一方探针 / 复现 / 红测试证实（rule 01）。
7. **枚举"类"，不是枚举实例。** 确诊的根因定义了一个缺陷的*类*；你
   观察到的那个实例只是碰巧先浮出水面的那个。全库清扫该类的每一个
   同类实例（Grep 定位、Read 确认——rule 04；清扫要汇报——rule 12）。
   范围注：清扫是"把被报告的问题修好"的一部分，不是范围溢出——
   rule 07 禁的是*没被要求*的改动。但当枚举出的类实质性扩大了用户
   请求的可见范围时，先把枚举结果上呈、拿到用户的决定，再做一趟式
   修复。
8. **机制只修一次。** 一次系统性修改，拆掉产生问题的机制，并在同一
   趟里覆盖枚举出的每一个实例。N 个症状共一个根因 = **一次**修复
   ——绝不是 N 个补丁，也绝不是"修被报告的那几个，剩下的同类不管"。
   "一次"的单位是机制，不是 diff 的体积：最小有效更改（rule 07）仍然适用。
9. **证明这个类已闭合**（rule 06）：验证不仅要重触发观察到的那个
   实例，还要至少重触发类里*另一个*被枚举出的实例。当清扫表明这个
   类只有一个成员时，显式说出来——清扫报告本身就是闭合证据。

实例修补陷阱，在本仓库身上的实测：一次审计点名了一条根因，却只修
了它见过的实例；机制活了下来，一个版本之后就再生出同一类的新一批
缺陷——其中包括一个倒退。下一趟换掉了机制（33 条 finding → 三个
根因 → 四个统一件），这正是本节规定的形态。同一形状的第二次失败，
是"类"在自我宣告——它施加的是"验证起源是否真的共享"的义务，绝不是
可以无视的巧合。

### 修改之中

10. **修根因，不修症状**（rule 03）—— 修改点应位于因果链的源头，而非现象处。
11. **完整覆盖影响范围** —— 同一根因的所有连带点一并修，不允许"先修一个明天再补"。
12. **不引入补丁标记** —— 屏蔽标记只有带理由注释才合法（见下方"为屏蔽标记写理由"）。
13. **不累加** —— 对同一文件的第三次小改正在路上时，就该停止打补丁：把待办的小修合并成一次系统式 Edit、用 `Write` 整体覆写、或者停下来告诉用户这个文件需要重构。删除永远不算补丁（净减少不计数），升版本号 / 改日期也不算——所以绝不要为了显得"系统"而给改动注水。
14. **新建/更新不变量必须记录** —— 若修改建立了新的不变量（"X 永远 ≠ None" / "必须先获取锁"），在代码或文档中显式声明。

### 批量机械替换（改名 / codemod / sed）

正则匹配你的意图，也匹配它的**同形异义**；而批量替换是唯一一种
"一条规则写错就同时污染上百个文件"的改动形态。动手之前：

1. **先勘察，后写规则。** 枚举目标 token 每一处出现的**真实上下文**并
   *把那份清单读一遍*。一次真实的目录改名里靠这一步抓出的同形异义：
   URL 里的 API 版本号（`…/v3/me`）、DB 表版本（`agent_subtypes v3/613`）、
   schema 区间（`Mesh v3/v4`）、**数学变量**（`v3 = v2 * v1 + …`）、
   函数参数、报告编号（`DIV-V3`）。盲目 sed 会把这六类全改坏。
2. **只改白名单形态。** 绝不"凡是匹配的都替换"——只替换勘察已证明
   确实是你所指的那些。
3. **必须产出拒绝报告。** 白名单拒绝掉的每一处都要打印出来给人读。
   静默跳过与"漏掉一处"在外观上完全无法区分。
4. **算术必须自洽。** 总命中数 = 已改写 + 已跳过 + 已拒绝。对不上就是
   规则错了，不是计数错了。
5. **预期会有正则天生看不见的形态。** token 藏在**正则选择分支**里
   （`^(?:v3|docs)/` —— 它后面跟的是 `|`，不是你所依据的分隔符）；
   token 作**独立参数**（`join(root, "v3", "assets")`）；以及**以它命名的
   符号**（`V3_DIR`）。每一类都需要独立的一趟勘察。
6. **绝不改写寻址历史的路径。** `git show <固定 rev>:<path>` 解析的是
   旧树，那里旧布局才是对的。工作树路径会搬家，寻址历史的路径不能跟着搬。

### 修改之后

15. 走 rule 06 收敛验证——**包括验证 2b**，因为批量替换正是"总数不变而
    构成已变"的典型场景；走 rule 07 任务忠实。

## 为屏蔽标记写理由

屏蔽标记——`# noqa`、`# type: ignore`、`// @ts-ignore`、`// @ts-expect-error`、
`// eslint-disable`（含 `-next-line` / `-line` 形态）、或用来等过竞态的
`time.sleep`——只有在同一行或紧邻的上一行 / 下一行的**注释里**带理由时才被允许：
`because` / `why` / `rationale` / `因为` / `原因` / `故意` 之类的 token，或
`see issue` / `intentional` / `third-party` / `per spec` 之类的说明引导词。
只认注释文本——同一个词出现在代码或普通字符串字面量里不算——而一个光秃秃的
延期词（TODO / FIXME / HACK / WIP / later）不是理由。块注释和 docstring 算注释，
URL 里的 `#` 不算。钩子的 `PATCH_MARKERS` 常量是权威的拼写清单；同一条理由
逃生口也服务于规则 10 与 11。

```python
# noqa: E501  -- URL string exceeds 100 chars; splitting hurts readability
LONG_URL = "https://..."
```

```typescript
// @ts-ignore: third-party lib has incomplete type, see issue #1234
const result = legacy.foo();
```

无理由的裸标记 = 偷懒，被拦截。

## 禁止做（MUST NOT）

- ❌ **症状式修补**：在调用点包 try/except 让异常消失，但**没改根因**。
- ❌ **静默屏蔽**：`# noqa` / `@ts-ignore` / `// eslint-disable` 无 why 注释。
- ❌ **竞态用 sleep 掩盖**：加 `time.sleep(0.5)` 让测试稳定通过 ≠ 修复竞态。
- ❌ **测试放宽**：原测试要求 X==5，改成 X>0 让它过。
- ❌ **超时拉长**：原 timeout=5s 拉到 60s 掩盖性能问题。
- ❌ **注释掉失败测试**：删除 / 注释 / `@skip` 失败用例当作"修好了"。
- ❌ **滚动补丁**：同一文件本会话 ≥ 4 次小幅 Edit 而**没有**一次系统性重写，属于反应式累加。写入门会计数；净减少与记账类改动豁免——两者都不累加。
- ❌ **修一个留三个 TODO**：不允许"先把这个修好其他下次再说"，必须一次性覆盖完整根因影响范围。
- ❌ **盲目批量替换**：跑改名 / codemod / sed 而事先没勘察 token 的真实上下文、没有白名单、或没有拒绝报告。
- ❌ **搬家时改写寻址历史的路径**：交给固定 git rev 的路径必须保持那个 rev 里真实存在的布局。
- ❌ **不变量是封闭集却写成模式黑名单**：若"只有名单内的名字合法"，就枚举那份名单并拒绝其余一切。只拉黑你碰巧见过的几种散件形态，下一种形态会直接走过去——包括在这道门**首次实跑**时。
- ❌ **点对点打补丁**：多处症状共享同一根因，却一处一处各修各的——包括"修被报告的那几处，没被报告的同类不管"。
- ❌ **实例加固**：修好了机制缺陷被观察到的那个实例，机制本身却原地不动、继续再生同类——加固只针对被看见的那一处，从不清扫整个类。

## 自检触发器

下列任一情况出现，agent 必须主动自检本规则：

- 即将做不超过 5 行的"快速修复"；
- 即将写 `try / except: pass` 或 `try / except: ...` 含糊处理；
- 即将写 `# noqa` / `@ts-ignore` / `eslint-disable` 而**不解释为什么**；
- 即将加 `time.sleep` 让测试稳定；
- 即将把测试断言放宽 / timeout 拉长；
- 注释掉 / `@skip` 任何失败的测试；
- 本会话内已对同一文件做过 ≥ 3 次小幅 Edit，仍在打补丁而不是重写；
- 即将跨多个文件跑改名 / codemod / sed，而没有勘察、白名单与拒绝报告；
- 即将为一个规格上是**封闭集**的不变量写一道枚举**坏形态**的守卫；
- 即将修的这个失败，和已经修过的某个**形状相同**——"类"在自我宣告；去诊断共同起源，别修补新冒头的这处；
- 即将动手写修复，却还没说明因果链停在哪里、为什么停在那里；
- 思维链里没有"根因 + 影响范围 + 方案对比"三件套。

## 终止条件

只有当下面**全部**成立时，才允许声称"修改完成"：

1. 已诊断出**最上游**根因——因果链已写明、诊断已被第一方证据证实（rule 03 上游阶梯 + rule 01）；
2. 已覆盖根因的所有连带点（rule 02 第 5 问）；
3. 已确诊之"类"的每一个同类实例都已枚举并在同一趟里修复——无点对点残留（统一修复）；
4. new_string 中无未带 why 注释的补丁标记（写入门通过）；
5. **最终回复**中已显式记录"根因 / 影响 / 方案对比"三件套（Stop layer (f) 通过）；layer (f) 只读最终回复文本——只留在思维链里的三件套不算数；
6. 已走完 rule 06 收敛 + rule 07 忠实自答。

否则 → **未达系统式修改**，回到 rule 02 + rule 03 + rule 08 重新分析。
