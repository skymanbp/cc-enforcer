# /cc-enforcer:checklist

> 无参数则依次输出 A–H 八份清单；参数为 `before` / `after` / `converge` / `fidelity` / `pre-edit` / `systematic` / `tldr` / `sync` 则只输出对应一份。
> 每份清单是对应规则正文的**勾选索引**，不复述规则：判定细节以 `rules/` 正文为准，钩子实际拦什么以各规则标题下的"强制执行"行为准。

请你（receiving agent）**逐项核对**，对每一条明确回答 ✅ / ❌ / N/A，并单独写明依据（`file:line` 或具体动作）。不允许笼统地说"都做了"。

---

## A. 修改前自检（`rules/01,02,04`）

- [ ] **A1 · 完整阅读** — 待改文件本会话已 `Read` 完整内容（不是 diff、不是 grep 命中行）。依据：文件 + 第几次工具调用。
- [ ] **A2 · 影响面探查** — 已 `Grep` 该文件 / 符号的所有引用点。依据：grep 命令与命中。
- [ ] **A3 · 上下游 Read** — 至少对 top-3 调用点 `Read` 过上下文。
- [ ] **A4 · 七问完成** — 规则 02 的七问（架构定位 / 职责 / 根源 / 方案触底 / 连带 / 风险 / 全局）各有一句回答。
- [ ] **A5 · 验证未猜测** — 关于 API、版本、行为的每个断言都有 `Read` / `Grep` / 命令输出依据（规则 01）。
- [ ] **A6 · 最小有效更改** — 只做被要求的事，没有顺手重构、投机抽象（定义见规则 07 检查 4）。

---

## B. 修改后自检（`rules/03,05`）

- [ ] **B1 · 根因 vs 症状** — 修改触达因果链的起源，而不是 try/except 静默、`--no-verify`、`time.sleep` 掩盖竞态、`@ts-ignore` 屏蔽类型。
- [ ] **B2 · 连带项已处理** — 需要同步改的下游、测试、文档已一并改了（列出）。
- [ ] **B3 · 新不变量已记录** — 修改建立的新不变量已写进代码注释或文档。
- [ ] **B4 · 引用可追溯** — 每个代码位置附 `file:line`，每条外部断言附链接 / 章节。
- [ ] **B5 · 半成品检查** — 留下的 TODO / FIXME / "暂时这样"已在回复中明确告知。

---

## C. 收敛验证（`rules/06`）—— 完成 B 之后必走 ⚠️

- [ ] **C1 · 重触发原症状** — 用用户最初的同一条命令 / 同一份输入重跑，附前后输出对照。
- [ ] **C2 · 边界 + 反向用例** — 至少 1 个边界场景（空 / 异常 / 并发 / 跨平台路径 / Unicode）+ 1 个反向用例（该失败的仍失败）。
- [ ] **C3 · 连带不破坏** — 跑了既有测试套件 / lint / 类型检查，附输出。
- [ ] **C4 · 自答 4 题** — 真的解决了吗（证据如何排除巧合 / 缓存 / 环境差异）？有没有更好的方案（对比维度）？哪些改动没被 C1–C3 触达、为什么不需要？验证对应原问题的哪个机理？
- [ ] **C5 · 量化证据**（涉及性能 / 竞态 / 兼容性时）— "快了"给数字、"稳定了"重跑 N ≥ 10 次、"兼容了"列测试矩阵。

> 任意 C 项答"不知道 / 应该可以 / 差不多"→ 未收敛，回到规则 02。"测试通过"不能替代 C1。

---

## D. 任务忠实（`rules/07`）—— 完成 C 之后必走 ⚠️

- [ ] **D1 · 拆解原始请求** — 回到用户**最初**那条消息，拆成可独立勾选的子项（动词命令 / 明示标准 / 隐含连带）。
- [ ] **D2 · 逐项核对** — 每个子项标 ✅（附证据）/ ⚠️（哪里降级、为什么、用户是否同意）/ ❌（原因）。
- [ ] **D3 · 标准达到性** — 用户的每个程度词（强制 / 完整 / 严格 / 所有 / 立即）都落地为硬证据；落成软建议即降级，必须修正或告知。
- [ ] **D4 · 范围不溢出** — 没做用户没要求的重构 / 改名 / 抽象；动过的无关文件已列出。
- [ ] **D5 · 半成品声明** — TODO / FIXME / 注释掉的测试已在最终回复显式列出。
- [ ] **D6 · 自答 3 题** — 覆盖性（拆成几项、做了哪些、没做的为什么）/ 标准性（每个程度词落成硬动作了吗）/ 忠实性（有没有偷换概念、有没有多做）。

> 任意 D 项答"应该 / 大概 / 主要部分都做了"→ 未达忠实。规则 06 的收敛报告不能替代 D6。

---

## E. 改前必读 · 写前必想（`rules/08`）—— 物理强制层 🚨

- [ ] **E1 · 目标文件已读** — 待改的每个文件本会话已 `Read` 完整内容。
- [ ] **E2 · 调用点已读** — 已 `Grep` 待改符号的引用点，并 `Read` 每处 ≥ 20 行上下文。
- [ ] **E3 · 连带文件已读** — 改 `rules/*.md` 时读了 `prompts/` / `commands/` / `docs/RULES.md`；改 hook 脚本时读了 `hooks/hooks.json` / `docs/ARCHITECTURE.md` §8 / 对应 `tests/test_*.py`。
- [ ] **E4 · 写前必想 ≥ 3 项已写进最终回复** — 根因 / 架构定位（含职责）/ 方案触底 / 连带影响 / 风险 / 方案对比。Stop layer (e) 只读最终回复，统计的是 rule-02 六组关键词（架构 / 职责 / 根因 / 方案 / 连带 / 风险）中的三组；"方案对比"不在其中。
- [ ] **E5 · 物理强制状态** — 若 `PreToolUse(Edit|Write)` 对 Edit DENY 过：已 Read 后重试，而**不是**用 `register_read.py` 登记一个并未真读的文件——钩子从磁盘重算 SHA-256，只有真的打开过文件才算得出摘要。

> 任意 E 项答"不知道 / 应该 / 凭感觉"→ 未达规则 08，回到 Read / Grep / 验证。禁止先 Edit 再补"我读过"。

---

## F. 系统式修改 · 禁止打补丁（`rules/09`）—— 物理强制层 🚨

- [ ] **F1 · 根因 vs 症状** — 修改点在因果链源头。依据：根因 file:line + 它如何引发症状。
- [ ] **F2 · 根因证据** — 根因判断当场验证过（Read / Grep / 命令输出）。
- [ ] **F3 · 完整覆盖** — 根因牵涉的所有连带点一次修完，没有"其他下次再说"。
- [ ] **F4 · 方案对比** — 至少对比了 2 个方案（简洁性 / 性能 / 架构契合度 / 维护性）。
- [ ] **F5 · 无补丁标记** — new_string 中没有下列裸标记（无紧邻 why 注释）。这是一份**封闭集**，逐条对应 [`read_guard.py`](hooks/scripts/read_guard.py) 的 `PATCH_MARKERS` 加上独立的 `try/except: pass` 结构扫描；少列一条，就会出现"每项都打了勾却仍被 DENY"：
  - [ ] 无 `try / except: pass` 静默吞错（结构扫描，不在 `PATCH_MARKERS` 里）
  - [ ] 无 `# noqa` 无解释（屏蔽 lint）
  - [ ] 无 `# type: ignore` 无解释（屏蔽 mypy）
  - [ ] 无 `// @ts-ignore` 无解释（屏蔽 TS）
  - [ ] 无 `// @ts-expect-error` 无解释（屏蔽 TS，与 `@ts-ignore` 同为独立一族）
  - [ ] 无 `// eslint-disable`（含 `-next-line` / `-line`）无解释
  - [ ] 无 `time.sleep(...)` 带 race / wait / workaround / hack / fix 注释掩盖竞态
  - [ ] why 注释写在**注释里**且被词法器认定为注释（URL 里的 `#` 不算；`/* … */` 块注释与独立成行的 docstring 算；中文 `因为` / `故意` 与英文 `because` 同等有效）
- [ ] **F6 · 未偷工放宽** — 没改宽测试、没拉长超时、没放宽断言、没注释 / `@skip` 失败用例。
- [ ] **F7 · 非滚动补丁** — 本会话对同一文件的**计入**小改 ≤ 3 次。净减少与记账类改动（版本号 / ISO 日期）不计入，不必为躲计数器而回避删除或给改动注水；系统式重写门槛含"跨越该文件的 ≥ 30%"，小文件整体重写即达标。
- [ ] **F8 · 新不变量已记录** — 修改建立的新不变量已在代码注释或文档里说明。
- [ ] **F9 · 最上游确认** — 因果链爬到机制 / 设计决策 / 缺失不变量为止；停在中途则点名真正起源 + 理由。
- [ ] **F10 · 确诊先行** — 动第一行代码前，根因假设已被第一方探针 / 复现 / 红测试证实。依据：探针命令 + 输出。
- [ ] **F11 · 同类清扫 · 统一修复** — 全库同类实例已枚举并一次修完；验证重触发了类里**另一个**实例（类只有一个成员时显式说明）。

> 任意 F 项答"不知道 / 应该可以 / 暂时"→ 未达规则 09，回到 rule 02 + 03 + 08。禁止：把"打补丁"包装成"最小有效更改"；`# noqa` 后只写规则号不写原因；用 sleep 让 flaky 测试"稳定"。

## G. 大白话 TL;DR 收尾（回复 schema）—— 物理强制层 🚨

- [ ] **G1 · YAML schema 收尾** — 回复末尾有 ```yaml `cc-enforcer:` 块；修改类用全量（改前 / 改中 / 收敛 / 忠实 / 收尾），非修改类用精简形（收敛 / 忠实 / tldr）。
- [ ] **G2 · tldr 存在** — schema 末尾有 `tldr:` 字段（或 `大白话:` / `一句话总结:` / `TL;DR:` 行）。
- [ ] **G3 · tldr 是人话** — 讲清"到底干了啥 / 结果如何 / 用户接下来要不要做什么"，不是复述规则检查。
- [ ] **G4 · tldr 长度** — 每条都是一句话且 ≤ 160 显示列（CJK 每字 2 列 ≈ 80 汉字）；多条内容逐条一行。

> 任意 G 项 ❌ → Stop layer (h) BLOCK（任何含 done-claim 的回复都查，不只 edit 轮）。补一行 `tldr: "<一句大白话>"`；超长则拆条 / 删过程细节，别删结果。

---

## H. 全库同步（`rules/12`）—— 物理强制层 🚨

- [ ] **H1 · 引用集枚举** — 对本次改动的符号 / 文件名 / 数量 / 版本 / 概念做过全库 Grep（代码 + 文档 + 测试 + 翻译）。
- [ ] **H2 · 逐项分类** — 每个命中标了"必须改" / "核对过无需改"，没有"没看"类。
- [ ] **H3 · 同会话连带更新** — 所有"必须改"都在本会话改了。
- [ ] **H4 · 清扫已汇报** — 收尾回复有 `同步核对:` / `sync-check:` 行，点名连带改了什么、核对过什么；占位值（`无` / `n/a` / `-` / 空）按缺失处理，写在围栏或引用块里的标记不算。
- [ ] **H5 · sync-gate 组满足** — `.claude/cc-enforcer/sync-gate.toml` 里 `when` 命中的组，`require` 侧有编辑，或 H4 的标记说明了为何无需改。
- [ ] **H6 · 不变量登记** — 本次暴露的新连带关系是否值得登记为新 sync-gate 组。

> 任意 H 项 ❌ 且组未满足 → Stop layer (i) BLOCK。没核对就写 `同步核对: 无需变更` 是规则 01 撒谎；门禁变绿不等于全库一致。

| ⚠️ | 部分 / 降级 + 说明 |
